# 3D models

`@blacklight/three` adds glTF models to 2D scenes. A `Model3D` is a game object like a sprite: it has a 2D position, rotation and scale, lives in a scene layer, sorts with `zIndex`, collides with its hitbox and plays animations with `play('walk')`. It is drawn by Three.js in the middle of Pixi's frame, through Pixi's own WebGL context, so 2D objects can be in front of and behind it.

```sh
pnpm add @blacklight/three three
pnpm add -D @types/three
```

`pnpm create blacklight my-game --template 2d-with-3d` starts from a working example: robots walking between a 2D background and a 2D foreground, a Draco-compressed model, a KTX2-textured crate, a portrait rendered to a texture and a pause menu showing a turning model.

```
scenes/arena/
├── arena.scene.ts
└── objects/robot/
    ├── robot.object.ts
    └── robot.glb          the model, found by name
```

```ts
import { behaviors } from '@blacklight/core';
import { Model3D } from '@blacklight/three';

export default class Robot extends Model3D {
  static override pixelsPerUnit = 110;
  static override animations = { wave: { loop: false, next: 'idle' } };
  static override behaviors = [behaviors.eightDirections({ speed: 260 })];

  override update() {
    this.play(this.velocity.length > 1 ? 'walk' : 'idle');
    if (this.velocity.length > 1) this.rotation3d.y = Math.atan2(this.velocity.x, this.velocity.y);
    this.zIndex = this.y;
  }
}
```

## Loading only where it is used

Three.js (about 180 KB gzip with the glTF loader) is part of the chunks of the scenes that import `@blacklight/three`, not of the game's entry. A title screen without 3D starts without it; the first scene with a model loads it with its other files, behind the loading screen.

Global objects (`objects/`) load with the first scene. Keep 3D objects in the folder of the scene that uses them (`scenes/<name>/objects/`), or Three.js loads with the first scene even when it has no model.

## Model files

A model is a `.glb` (one file) or a `.gltf` with its `.bin` and textures next to it. Put it in the object's folder, named after the folder (`objects/robot/robot.glb`), or point at it:

| `static model`        | Finds                                           |
| --------------------- | ----------------------------------------------- |
| omitted               | `<folder>/<name>.glb` or `<folder>/<name>.gltf` |
| `'./robot-lod1.glb'`  | relative to the object's folder                 |
| `'@models/robot.glb'` | `models/robot.glb` at the project root          |
| `'robot'`             | the asset named `robot` anywhere                |

The model of every object class a scene can spawn is preloaded with the scene, like sprite sheets; `.glb` and `.gltf` files listed in the scene's `static assets` or placed in its `assets/` folder are preloaded too. `spawn(Robot, { model: '@models/other.glb' })` and `setModel()` show another preloaded file. A `.gltf` finds its `.bin` and textures through the game's asset list, so they keep working after the build renames them; a reference to a file outside the project is an error that names it.

Several objects showing the same file share its geometry, materials and textures; skinned models get their own skeleton. To change a material for one object, clone it in `create()` (`object3d` already holds the model there):

```ts
override create() {
  this.object3d.traverse((node) => {
    if (node instanceof Mesh) node.material = node.material.clone();
  });
}
```

### Draco and KTX2

Files compressed with Draco (`KHR_draco_mesh_compression`) and textures in KTX2 / Basis (`KHR_texture_basisu`) load without setup. The decoders come from the `three` package: the build copies them into `dist/assets/` (1.9 MB with the fallbacks) and a game downloads only what a file needs: about 350 KB for Draco, 590 KB for Basis. Nothing is fetched from a CDN, so compressed models work offline, in Electron and in the mobile WebView.

The decoders run in Web Workers created from `blob:` URLs and compile WebAssembly. A Content-Security-Policy must allow `worker-src blob:` and `script-src 'wasm-unsafe-eval'` for compressed files.

To compress an existing model: `npx @gltf-transform/cli draco in.glb out.glb` and `npx @gltf-transform/cli etc1s in.glb out.glb` (needs KTX-Software's `toktx`).

## Placement

The model's origin sits at the object's position. One model unit (glTF units are meters) is `pixelsPerUnit` virtual pixels; y up in the model is up on screen and z points at the viewer, so a character exported standing, facing +z, stands on the object's position and faces the player.

| Property                  | Default          | Meaning                                                                                     |
| ------------------------- | ---------------- | ------------------------------------------------------------------------------------------- |
| `static model`            | by folder name   | Model file (see above).                                                                     |
| `static pixelsPerUnit`    | `100`            | Virtual pixels per model unit.                                                              |
| `static view`             | the layer's view | Own camera and lights (see below).                                                          |
| `static animations`       | none             | Loop, chaining, speed, fade and events per animation.                                       |
| `static defaultAnimation` | first clip       | Played on spawn.                                                                            |
| `static renderToTexture`  | `false`          | Draw into a texture shown as a sprite ([Render to texture](./3d-render-to-texture)).        |
| `static hitbox`           | `'auto'`         | The model's rest box in 2D (width × height, ignoring `rotation3d`).                         |
| `rotation3d`              | `(0, 0, 0)`      | Three.js `Euler` of the model, in radians. `rotation` stays the 2D rotation.                |
| `z`                       | `0`              | Depth towards the viewer, in virtual pixels: nearer looks bigger with a perspective camera. |
| `object3d`                | —                | The model's root (Three.js `Group`): add meshes, lights that follow it, change materials.   |
| `loaded`                  | —                | The loaded file: `scene`, `animations`, `box`, `sphere`, `triangles`.                       |

`x`, `y`, `rotation`, `scale`, `zIndex`, `visible`, the layer and the 2D camera apply as for any object. A model in a split-screen scene appears in every view. Mirroring with `scale.x = -1` mirrors the model.

## Layers, cameras and lights

The models of one scene layer share a camera type and lights: the scene's `static layers3d` sets them per layer.

```ts
import { Scene } from '@blacklight/core';
import type { Layers3D } from '@blacklight/three';

export default class Arena extends Scene {
  static override layers = ['back', 'actors', 'front'];
  static layers3d: Layers3D = {
    actors: { camera: 'perspective', fov: 35, sun: { from: [-0.5, 1, 0.9], intensity: 2.6 } },
  };
}
```

Here the `back` layer draws behind every model and `front` over them; inside `actors`, models and sprites sort by `zIndex` like sprites do.

| Option    | Default                                    | Meaning                                                                                                         |
| --------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `camera`  | `'orthographic'`                           | `'orthographic'` keeps sizes; `'perspective'` makes near parts bigger, seen from the center of the screen.      |
| `fov`     | `40`                                       | Vertical field of view of the perspective camera, in degrees.                                                   |
| `ambient` | `0.9`                                      | Intensity, or `{ color, intensity }`, of the light reaching every surface.                                      |
| `sun`     | `{ from: [-0.6, 1, 0.8], intensity: 2.4 }` | Directional light coming from `from` (screen space: x right, y up, z towards the viewer); `false` turns it off. |

Lights are in screen space: a sun from the top left lights every model from the top left of the screen, whatever the 2D camera does. `view3d(scene, 'actors')` returns the layer's `View3D` to change it at run time (`configure({...})`) or to add any Three.js light to its `scene`. A model with `static view` uses its own instead.

Both cameras keep the 2D placement exact at depth 0: the model's origin is drawn where a sprite at the same position would be. A perspective camera looks at the center of the screen (or of the split-screen view, or of the texture), at a distance that gives the field of view; parts of the model nearer than the depth-0 plane look bigger.

Each model is drawn on its own: it clears the depth buffer first, so models never cut into each other. Which one is in front is decided by 2D order (`zIndex`, layer, spawn order), as for sprites.

## Animations

The skeletal and node animations of the file are its clips, by name. `play`, `queue`, `onEnd` and `onFrame` work as on sprites, on the fixed step: they pause with the game, follow `game.time.scale`, and are saved in snapshots.

```ts
this.play('walk'); // keeps running when called every step
this.play('attack', { restart: true }); // starts over
this.play('run', { speed: 1.5, fade: 80 });
this.queue('idle'); // after the current non-looping clip
this.onEnd((name) => {});
this.onFrame('step', () => this.scene.audio.play('step'));
```

| Setting (`static animations`) | Default                      | Meaning                                                   |
| ----------------------------- | ---------------------------- | --------------------------------------------------------- |
| `loop`                        | `true` (`false` with `next`) | Repeats.                                                  |
| `next`                        | none                         | Clip played when this one ends.                           |
| `speed`                       | `1`                          | Playback rate.                                            |
| `fade`                        | `150`                        | Cross-fade from the previous clip, in ms (`0` cuts).      |
| `events`                      | none                         | `{ 0.4: 'step' }`: seconds into the clip → event name(s). |

A missing name falls back like on sprites, with one warning: `walk-left` plays `walk-right` mirrored, then `walk`, then the first clip. A model without any clip throws on `play` with the reason.

## Shared WebGL context

Three.js renders into Pixi's WebGL context: one canvas, one context, textures and buffers in one GPU memory. At each model, Pixi's batch is flushed, the target Pixi has bound (screen, split-screen view, filter texture, render texture) receives the model, then both renderers reset their cached GL state (`resetState()` on each) and Pixi binds its target again. Pixi must run on WebGL (the default); a game forcing Pixi's WebGPU renderer gets an error at the first model. `sharedContext(game.app.renderer).renderer` is the Three.js renderer, for statistics (`info.render`) or advanced use.

## Performance

`scenes/bench` of the template draws two animated 10 000-triangle models between 2D layers and reports frame rate and main-thread time per frame (open `/#bench`, or `/#bench-2d` for the same scene without models). The automated gate runs it on a release build with a Galaxy A54-sized viewport (915 × 412, pixel ratio 2.625) and the CPU slowed four times:

| Machine                                    | Scene      | fps  | CPU per frame (mean / p95) |
| ------------------------------------------ | ---------- | ---- | -------------------------- |
| Desktop, Radeon RX 6650 XT, CPU ×4 slower  | 2D only    | 59.9 | 2.17 / 5.9 ms              |
| Desktop, Radeon RX 6650 XT, CPU ×4 slower  | two models | 60.0 | 4.90 / 9.7 ms              |
| Same, software GPU (SwiftShader, as in CI) | 2D only    | 16.6 | 2.20 / 4.6 ms              |
| Same, software GPU (SwiftShader, as in CI) | two models | 10.4 | 5.46 / 10.2 ms             |

The software GPU draws on the CPU, which is why CI checks the main-thread time (under 8.3 ms mean, 16.7 ms at the 95th percentile) and checks 60 fps only when a hardware GPU is present. Real phones are in the manual checklist.

Each model costs one draw pass with two GL state resets. Many small models in one layer cost more than one model holding them all: group static props into one file.

## Limits

- Masks, Pixi filters, `alpha` and `tint` of a directly drawn model are ignored, and a model inside a filtered container draws without them: use [render to texture](./3d-render-to-texture) for those.
- Models do not intersect each other in depth: 2D order decides which one covers the other. Several meshes that must intersect belong in one file.
- No shadows, no environment maps, no post-processing: the lights are ambient, one directional sun, and any Three.js light added to a layer's `scene`.
- `hitbox: 'auto'` is the model's rest box; it ignores `rotation3d` and animation. Give a fixed `hitbox` for precise collisions.
- Pixel-art mode does not apply to models (they are drawn at the screen's resolution, smoothed).
- Global objects load with the first scene: a 3D object in `objects/` brings Three.js into the first scene.
