# Tutorials

Each tutorial explains one part of the engine in a few paragraphs, then gives you exercises to do in the page: a running example, and a button that opens its code in a full-screen editor next to a second preview, with the task beside it. The preview restarts a moment after you stop typing, so you see the effect of each change at once. The tutorials can be read in any order; the table below follows the order of the guide. Inside a tutorial, do the exercises in order: each one starts from the code the previous one ended with.

An exercise has four parts, in the panel under the preview of its popup:

- **The task**: what to change, and what you should see once it works.
- **The status line**, on exercises the page can check by itself: **Checking** with what it looks for, then **Done** once the running example does it. The check reads the running game, not your code, so any solution that works passes.
- **Hint**: a pointer to the API to use, folded until you open it.
- **Solution**: a button. It loads the finished file into the editor and marks the lines it changed, keeping your own code; press it again, now **Revert**, to get your code back. **Reset**, next to the file name, goes back to the starting code.

Click a preview to give it the keyboard (arrows or WASD move, Space jumps, Enter confirms, Escape pauses). The examples run the real engine in a sandboxed frame; nothing you type leaves the page. Every starting file and every solution is type-checked and run by the test suite on each change of the engine, so a solution loaded here works with the current version.
