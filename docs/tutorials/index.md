# Tutorials

Each tutorial explains one part of the engine in a few paragraphs, then gives you exercises to do in the page: a running example, its code in an editor next to it, and a task that changes the code. The preview restarts a moment after you stop typing, so you see the effect of each change at once. Do them in order; each exercise starts from the code the previous one ended with.

An exercise has four parts:

- **The task**: what to change, and what you should see once it works.
- **The status line**, on exercises the page can check by itself: **Checking** with what it looks for, then **Done** once the running example does it. The check reads the running game, not your code, so any solution that works passes.
- **Hint**: a pointer to the API to use, folded until you open it.
- **Solution**: the finished file with the changed lines highlighted. The **Solution** button of the editor loads it into the preview; **Reset** goes back to the starting code.

Click a preview to give it the keyboard (arrows or WASD move, Space jumps, Enter confirms, Escape pauses). The examples run the real engine in a sandboxed frame; nothing you type leaves the page. Every starting file and every solution is type-checked and run by the test suite on each change of the engine, so a solution shown here works with the current version.
