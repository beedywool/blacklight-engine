# Decisions

Every choice `SPEC.md` left open, one line each: `date · topic · choice · why`.

- 2026-10-29 · npm scope · keep `@blacklight`, `create-blacklight`, `blacklight-vscode` · none of these names has a published package (registry 404, scope search empty). npmjs.com refuses unauthenticated checks of org ownership, so the owner must create the `blacklight` npm org before the first publish; if it is taken, switch to `@blacklight-engine` and record it here.
- 2026-10-29 · TypeScript version · 6.0.3, not 7.0 · typescript-eslint 8.72 (required for linting) supports TypeScript < 6.1; move to 7 when typescript-eslint supports it.
- 2026-10-29 · package manager · pnpm 12.16.1, installed by each developer (https://pnpm.io/installation) and pinned in `packageManager` · current release at project start; contributors install pnpm and the dependencies before anything else, no wrapper. Install scripts are opt-in (`allowBuilds` in `pnpm-workspace.yaml`): only esbuild for now.
- 2026-10-29 · Vite entry · the CLI writes `index.html` and `main.ts` into `<game>/.blacklight/` (git-ignored) and roots Vite there · games have no boilerplate HTML or bootstrap file, and the output lands at `dist/index.html` without renaming.
- 2026-10-29 · build base URL · `./` (relative) · the same web build must load from a web path, Electron's custom protocol and Capacitor's WebView.
- 2026-10-29 · scene discovery · `import.meta.glob('../scenes/*/*.scene.{ts,js}')`, file name must equal folder name · one chunk per scene (RT-03) with no registration code; the name check catches typos at startup.
- 2026-10-29 · config validation · hand-written validator in core, no schema library · keeps `@blacklight/core` small (NF-04); errors list every field with its fix.
- 2026-10-29 · display objects before RT-05 · core re-exports PixiJS `Container`, `Graphics`, `Sprite`, `Text` · templates import only from `@blacklight/core`; the engine's own classes replace them in phase 1 under the same names.
- 2026-10-29 · fixed-step epsilon · 1e-6 ms tolerance in the accumulator · float drift otherwise drops a step (144 frames of 1000/144 ms made 59 steps instead of 60).
- 2026-10-29 · docs fonts · Google Sans Flex (SIL OFL 1.1) bundled from blacklight-website · OFL is not in SPEC §9's list but allows bundling and redistribution with any software; it is used only by the docs site, never shipped in games.
- 2026-10-29 · docs branding · BlackLight black theme and hanging-bulb logo from blacklight-website · owner asked for the docs to follow blacklight-sso / blacklight-website.
- 2026-10-29 · engine linking for local tests · `create-blacklight --link <checkout>` writes `link:` dependencies; the dev server allows the linked workspace in `server.fs.allow` · lets the phase gates scaffold and run a real project against unpublished packages.
- 2026-10-29 · logical vs display position · `GameObject.x/y` hold the logic position; the display (`position`) is interpolated between steps · rendering at 144 Hz stays smooth while logic runs at 60 Hz; `teleport()` skips the interpolation.
- 2026-10-29 · display objects · engine classes extend Pixi `Container` and hold the Pixi object (`view`, `draw`) instead of extending Pixi `Sprite`/`Text` · one base class (`GameObject`) for every object; Pixi classes cannot share a base otherwise.
- 2026-10-29 · object discovery · `objects/<name>/<name>.object.ts` and `scenes/<s>/objects/<name>/…` are found by glob and named in PascalCase after the folder · names survive minification; `spawn('Name')` and `is('Name')` work without registration code.
- 2026-10-29 · asset preloading · a scene preloads its `static assets`, everything in `scenes/<name>/assets/`, and the files of every object class it can spawn; fonts in `assets/` load at start · sprites and sounds can then be used synchronously; global `assets/` stays on demand so big games do not load everything at boot.
- 2026-10-29 · asset manifest · the CLI scans the project and serves a virtual module (`virtual:blacklight/assets`) mapping project paths to URLs · Pixi would otherwise need hand-written bundles; file renames are picked up by the watcher.
- 2026-10-29 · atlases · release builds pack PNGs up to 1024 px into 4096² shelf-packed pages with 2 px extruded padding (pngjs); dev serves the files directly · RT-08; JPEG/WebP stay separate (rarely small sprites).
- 2026-10-29 · texture resolution · textures load with resolution 1 · Pixi reads `@16x16` in grid sheet names as an `@16x` HiDPI suffix.
- 2026-10-29 · Motion · easings and spring math come from Motion; the tween scheduler is the engine's, on the fixed step · Motion's own frame loop runs on requestAnimationFrame and would not pause with the game or replay deterministically (RT-14).
- 2026-10-29 · gamepad database · SDL_GameControllerDB is bundled in core as a lazy chunk (612 KB raw), refreshed with `pnpm --filter @blacklight/core update:gamepads`; only loaded when a pad without the standard mapping connects · offline play, no download at runtime.
- 2026-10-29 · player 1 and gamepads · player 1 reads every device until a second player joins; then it keeps the keyboard and the first pad it used · solo games need no setup, join screens still work.
- 2026-10-29 · typed names · the CLI writes `.blacklight/types.d.ts` (Register: scenes, objects, actions, animations, assets) on dev, build and `blacklight types`; scenes, objects and actions are strict unions, animation and asset names are suggestions · CLAUDE.md asks for typed names; animations and assets also accept computed strings.
- 2026-10-29 · `.anim.json` typing · `static animations` accepts the JSON import type (`AnimationFileInput`), hitboxes are checked by the JSON Schema rather than TypeScript · JSON imports do not have literal types, so `"type": "box"` would not narrow.
- 2026-10-29 · physics package · `@blacklight/physics` awaits Rapier's WebAssembly at import (top-level await) and steps one world per scene on the fixed step · rigid bodies can be created synchronously in `create()`.
- 2026-10-29 · snapshots · `scene.snapshot()` saves core fields, the fields a subclass declares (or `static serialize`), references as ids, behavior and animation state, random state and cameras as JSON; timers are kept in memory only · closures cannot be serialized; rollback runs in memory, saves do not need timers.
- 2026-10-29 · test fixture · `e2e/fixtures/runtime` is a small game in the workspace, assets generated by `e2e/fixtures/generate-runtime-assets.mjs` · gates need a real project; generated art avoids licensing questions.
- 2026-10-29 · screenshot references · one reference per screenshot for all OS (`snapshotPathTemplate` without platform), 1 % pixel tolerance, gate scenes avoid text · font rendering differs between OS; shapes and pixel art do not.
- 2026-10-29 · collision masks · one-sided: `a.onCollide(b)` only when `b`'s layer is in `a`'s mask; solids block a mover only when the solid's layer is in the mover's mask · matches Godot/Phaser, so a pickup with an empty mask can stay silent while the player hears it.
- 2026-10-29 · physics stepping · packages hook into `scene.afterObjects` (after objects, before collision detection); Rapier bodies turn hitbox events off (`collision.events = false`) · one world step per scene step whatever the object order, and contacts are reported once.
- 2026-10-29 · restoring re-created objects · `restore()` calls `onRestore()` instead of `create()` · `create()` may spawn children or play sounds that the snapshot already contains.
- 2026-10-29 · camera shake randomness · cameras draw shake from a cosmetic generator, not `scene.random` · visual effects must not change the gameplay sequence (replays, rollback).
- 2026-10-29 · UI layer · `@blacklight/ui` is a Vue app over the canvas, sized to the design area in virtual pixels and scaled like the canvas; core only knows a `UiHost` interface and `game.plugins` · games without UI do not ship Vue; `scene.ui` stays typed in core.
- 2026-10-29 · screens · a screen is any Vue component; named screens are the `.vue` files of `ui/` and `scenes/<s>/ui/`, loaded on demand · same discovery rule as scenes and objects; `this.ui.push('PauseMenu')` without imports.
- 2026-10-29 · focus · DOM-based spatial navigation (`data-bl-focus`, groups with wrap/trap/axis), aligned elements preferred, diagonals only reach elements in both directions; key repeat 380 ms then 90 ms · Persona-style menus are lists and grids; pointer and touch move the same focus.
- 2026-10-29 · UI input · the UI reads actions through `input.uiPlayer(n)`; screens that block input set `input.blocked`, so game code reads idle actions · game objects need no "is a menu open" checks.
- 2026-10-29 · UI timing · UI timelines and transitions run in real time by default (menus animate while the game is paused); `useTimeline('game')` follows the game clock · RT-14 asks tweens to pause with the game; a pause menu must still animate, so UI chooses per timeline.
- 2026-10-29 · prompt glyphs · Kenney Input Prompts 1.5 (CC0, supplied by the owner from kenney.nl) vendored in `packages/ui/prompts` (filled SVGs of Xbox, PlayStation, Switch, keyboard & mouse, touch; 378 files, 1.5 MB); referenced through a generated `new URL()` module kept out of the library bundle · Vite library mode inlines assets (580 KB bundle); this way games emit the files and browsers load only the glyphs shown.
- 2026-10-29 · pad family · from the gamepad id: Xbox first (045e, "xbox"), then Sony (054c, "Wireless Controller"), then Nintendo (057e); unknown pads use Xbox art · "Xbox Wireless Controller" contains Sony's product name.
- 2026-10-29 · Persona fonts · the persona theme uses system display fonts (Impact, Arial Black, Arial Narrow); no font file ships · no MIT/CC0 condensed display font was available offline; games put theirs in `assets/`.
- 2026-10-29 · UI screenshots · per-platform references (`e2e/__screenshots__/ui.spec.ts/ui/<platform>/`), missing references are written on first run (`updateSnapshots: 'missing'`) and uploaded by CI · DOM text renders differently on each OS.
- 2026-10-29 · linting Vue · `eslint-plugin-vue` (flat/essential) with the TypeScript parser; single-word component names allowed · screens are named after files (`Hud.vue`).
- 2026-10-29 · pause and sound · `game.pause()` fades the music, sfx and voice buses out and keeps the `ui` bus; hiding the window still suspends the whole audio context · pause menus need their sounds; the spec does not say how paused audio behaves.
- 2026-10-29 · missing UI theme · a saved or configured theme name that is not registered yet draws with `blacklight` (one warning) and keeps the name; `ui({ themes })` registers themes before startup · a saved custom theme must not stop the game from starting.
- 2026-10-29 · named screens · the runtime waits for a named screen's module before adding it to the stack · its enter transition plays with content and `useScreen()` options apply the first time.
- 2026-10-29 · phase 3 split · seven parallel areas, each owning its files: 3a UI complete (`packages/ui`, `templates/visual-novel`, CLI font subsetting in `packages/cli/src/fonts.ts`); 3b 3D (`packages/three`, `templates/2d-with-3d`); 3c desktop (`packages/native`, saves in `packages/core/src/save/`, hardening, CLI targets win/mac/linux/steam in `packages/cli/src/targets/desktop.ts`, `sign` in `commands/desktop.ts`); 3d mobile (`packages/mobile`, CLI targets android/ios in `targets/mobile.ts`); 3e modules and services (`packages/core/src/modules/`, `packages/modules/*`, `packages/registry`, `servers/reference`, `defineNative` in `packages/native/src/define-native.ts`, CLI add/search/publish in `commands/registry.ts`, MOD-04 check in the Vite plugin); 3f networking (`packages/net`, `servers/relay`, `packages/eslint-plugin`); 3g tooling (`packages/vscode`, CLI doctor/lint/run in `commands/tools.ts`, hot reload). Shared contracts: `Platform` (`packages/core/src/platform.ts`) with reserved native module names, the CLI `targets` registry and one `register…Commands(cli)` call per area in `cli.ts`. Shared files take appended lines only (DECISIONS, MANUAL_TESTS, THIRD_PARTY_LICENSES) or the area's own lines (PROGRESS, docs sidebar group).
- 2026-10-29 · platform interface · `game.platform` (files, per-install save key, `invoke` for native calls, events, openUrl, quit) defaults to `WebPlatform` (IndexedDB, non-extractable WebCrypto key); desktop and mobile packages replace it from a game plugin · saves, accounts and modules are written once against one interface.
- 2026-10-29 · mobile config (core change) · `mobile { orientation, statusBar, keepAwake, playGamesAppId, gameCenter }` validated in `packages/core/src/config-mobile.ts`; `config.ts` only imports it, adds the field and one call · SPEC §6.2 lists orientation and statusBar; keep-awake and the two achievement switches belong to the same section. Defaults: orientation from the resolution, bars hidden, screen kept on.
- 2026-10-29 · mobile install · `blacklight build --target android|ios` injects `mobile()` first in the generated entry's plugin list (Vite transform in the mobile build only); web builds never ship Capacitor; games need not depend on `@blacklight/mobile` (the CLI's copy is aliased) · templates build for mobile without code changes (SPEC §12).
- 2026-10-29 · native project location · Capacitor project generated in `<game>/.blacklight/mobile/` (git-ignored), regenerated from `game.config.ts` and synced on every build; native files of the game go in `<game>/mobile/android|ios/`, copied over it · no native folders to maintain or merge for a web developer; Capacitor's own `android/`+`ios/` layout would put Gradle/Xcode projects in the game repository.
- 2026-10-29 · mobile outputs · `release/android/<name>-<version>[-debug].apk|.aab` and `release/ios/<name>.app|.ipa`; `release/` added to `.gitignore` and the templates' `_gitignore` · `dist/` is emptied by every web build. Desktop targets can share `release/<target>/`.
- 2026-10-29 · Capacitor plugin resolution · the generated app root gets a `package.json` and `node_modules` links (junctions on Windows) to the Capacitor packages resolved from `@blacklight/mobile`, listed in `includePlugins` · pnpm's strict layout hides transitive packages from Capacitor's CLI; games keep a single dependency.
- 2026-10-29 · mobile plugins · `@capacitor/app`, `browser`, `filesystem`, `haptics`, `screen-orientation`, `@capacitor-community/keep-awake`, `capacitor-secure-storage-plugin`, the core `SystemBars` plugin (no `@capacitor/status-bar`), plus `@capacitor-community/sqlite` only when the game uses SQLite (dependency ending in `sqlite`, `modules.sqlite` in the config, or `--sqlite`) and every Capacitor plugin in the game's dependencies · SQLCipher adds several MB per ABI.
- 2026-10-29 · achievements native code · no maintained MIT Capacitor 8 plugin for Game Center or Play Games v2 exists (openforge's is Capacitor 5); `@blacklight/mobile` is itself a Capacitor plugin (`BlacklightGames`: Kotlin `android/`, Swift `ios/` + `Package.swift` + podspec). Kotlin because `@capacitor/filesystem` already brings the Kotlin toolchain.
- 2026-10-29 · Play Games SDK licence · `play-services-games-v2` is under Google's proprietary SDK terms (like Steamworks, SPEC §9), so it is compiled in only when `mobile.playGamesAppId` is set (Gradle property `blacklightPlayGames`, a stub source set otherwise) · other games ship only MIT/Apache/BSD code.
- 2026-10-29 · native module contract (mobile side) · `sqlite`: `open(name, { readOnly? })`, `execute(name, sql, params?) → { changes, lastInsertId? }` (no params: several statements), `query(name, sql, params?) → rows`, `close(name)`; database names `[\w-]+`. `gamecenter` / `playgames`: `signIn() → { authenticated, playerId?, displayName? }`, `unlock(id)`, `progress(id, current, total)`, `show()`. `secure-storage`: `get/set/remove/keys`, keys `blacklight.*` reserved. `haptics`: `impact(style)`, `notification(type)`, `vibrate(ms)`, `selection()`. `app`: `info`, `exit`, `minimize`, `orientation`, `keepAwake`, `statusBar`, `launchUrl` · the modules agent's sqlite and achievements modules call these names; desktop (better-sqlite3) should answer the same four sqlite methods.
- 2026-10-29 · defineNative on mobile · an unknown module name in `MobilePlatform.invoke` goes to the Capacitor plugin of that name as `plugin[method]({ args })`, answered with `{ value }`; `platform.register(name, methods)` adds JavaScript-only modules · one convention for the modules agent's `defineNative` mobile part (MOD-03).
- 2026-10-29 · back button · Android back presses the `back` action of player 1 for 100 ms through `PlayerInput.virtual` (one `pressed` step whatever the bindings) and raises platform `back`; the app never closes on its own · menus already handle `back`; quitting is the game's decision (`platform.quit()`).
- 2026-10-29 · app background · the platform's `pause`/`resume` dispatch `blur`/`focus` on `window`, reusing core's `pauseOnBlur` path · the Android WebView does not report `visibilitychange` when the app goes to the background (seen on the emulator).
- 2026-10-29 · mobile files · `Directory.Data` + `blacklight/` (Android `files/`, iOS Documents), atomic write = `<file>.tmp` then rename, delete-then-rename on iOS; a leftover `.tmp` is promoted on read · SV-02 app-private storage, SV-04 atomic writes with what Capacitor's Filesystem offers.
- 2026-10-29 · mobile save key · 32 random bytes in `capacitor-secure-storage-plugin` (Android Keystore-wrapped, iOS Keychain) under `blacklight.saveKey`, imported as a non-extractable AES-GCM `CryptoKey`; a key that exists but cannot be read is an error, never replaced · replacing it would make every save unreadable.
- 2026-10-29 · deep links · URL scheme = the game id (`com.example.game://`), added to the Android manifest and `Info.plist`; links before the first `deeplink` listener are queued · the OIDC module (SVC-01) can use `<id>://callback` as redirect URI with no extra config.
- 2026-10-29 · SEC-07 (mobile part) · `webContentsDebuggingEnabled` and native console logging follow `--release` in the generated `capacitor.config.json`; the mobile web bundle is always a production build · the 3c owner of SEC-07 can check it off with `packages/cli/test/mobile.spec.ts` and the release test of `e2e/mobile-android.spec.ts` (no DevTools socket for a signed release APK on the emulator).
- 2026-10-29 · Gradle and Java · the CLI switches the generated wrapper to the `-bin` Gradle distribution and picks a JDK 21–24 (`JAVA_HOME`, PATH, Android Studio's JBR, `/usr/lib/jvm`) · Gradle 8.14 refuses newer Java, and developers often have a newer default JDK.
- 2026-10-29 · `run --target android|ios` · `runMobile(target, options)` in `packages/cli/src/targets/mobile.ts` builds a debug app, installs and starts it (adb / simctl), registered as `runners.android` / `runners.ios` (3g registry); `build --target android --run` does the same · the tooling area owns the `run` command. Signing variables follow 3g's doctor: `ANDROID_KEYSTORE`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `APPLE_TEAM_ID`; doctor's Java check uses the build's JDK search (21–24).
- 2026-10-29 · iOS outside macOS · `--target ios` generates and syncs the Xcode project, then fails with an explanation; `--dry-run` stops there successfully · Xcode only exists on macOS.
- 2026-10-29 · iOS Simulator e2e · Playwright cannot drive WKWebView: the fixture mirrors its state to `status.json` in its container, a deep link stands in for the tap that makes a save; real touches on iOS are in MANUAL_TESTS.md · simctl has no touch input and XCUITest would need a test target in the generated project.
- 2026-10-29 · mobile native names aligned with phase 3e (supersedes the contract line above where they differ) · `secure-storage.get` → string or `null`; `sqlite` database names follow `DATABASE_NAME` of module-sqlite (`game.db`), `execute` always returns `lastInsertId` (0 when none), booleans bound as 1/0, `Uint8Array` as blobs (back as `Uint8Array`); `gamecenter`/`playgames` add `submitScore(board, score)` and `scores(board, limit) → [{ rank, name, score }]` (all-time public top, at most 25) and sign the player in before any call that needs it (the achievements module never calls `signIn`) · one protocol for every backend; the redirect URI `<game id>:/oauth/callback` is served by the `<game id>` scheme already registered.
- 2026-10-29 · 3D in the Pixi frame · `Model3D` holds a Pixi `RenderContainer`; at its place in Pixi's instruction list Three renders into the framebuffer and viewport Pixi has bound, with a projection built from Pixi's own projection and world matrices, then both renderers `resetState()` and Pixi rebinds its target · 2D order (layers, zIndex) decides what covers a model with no extra pass, and the same code draws into the screen, split-screen views and render textures.
- 2026-10-29 · 3D view space · lights and the perspective eye live in render-target space (x right, y up, z towards the viewer, origin at the target's center); the z = 0 plane matches the 2D placement exactly · a model at depth 0 lines up with the sprites around it; "light from the top left" means the screen's top left whatever the 2D camera does.
- 2026-10-29 · 3D depth · each model clears the depth buffer before drawing; models do not intersect each other · they are ordered like sprites; one shared depth would need one 3D scene per layer and break interleaving with 2D objects.
- 2026-10-29 · 3D camera per layer · `static layers3d` on the scene (`{ actors: { camera: 'perspective', fov: 35, ambient, sun } }`), `view3d(scene, layer)` at run time, `static view` on a model to override · spec asks for a camera per 3D layer; configuration through static properties like `static layers`.
- 2026-10-29 · core hooks for 3D · `AssetStore.registerLoader(extensions, loader)` + `assets.get(path)` (packages teach the store new file types), `GameObject.requiredAssets()` (files a class needs, preloaded like `static assets`) · `.glb` files then go through the per-scene preload with progress (3D-06) without core knowing Three.js.
- 2026-10-29 · Draco / KTX2 decoders · use three's own `DRACOLoader` / `KTX2Loader`, which reference their decoders with `new URL(…, import.meta.url)`: Vite emits them into `dist/assets/`; the loaders are imported only when a file declares the extension · offline by construction, no copy step; a game that never uses compressed files downloads nothing extra (the files sit unused in dist, about 1.9 MB with the asm.js fallback).
- 2026-10-29 · KTX2 format detection · a throwaway WebGL 2 context answers which compressed formats the GPU supports, then is released · files load before the first model draws (no Three renderer yet), and the answer depends only on GPU and browser.
- 2026-10-29 · models in Vue screens · `<ModelView>` (`@blacklight/three/ui`) renders to a Pixi render texture in the shared context and copies it with `readPixels` into its own 2D canvas each frame; no change to `@blacklight/ui` · DOM cannot display a WebGL texture of another canvas; a second WebGL context would duplicate every model and texture in GPU memory.
- 2026-10-29 · 3D budget in CI · the benchmark measures fps and main-thread time per frame; CI (no GPU, SwiftShader) asserts the CPU budget under a 4× CPU throttle with an A54-sized viewport, and 60 fps only when a hardware GPU is present; real phones are in MANUAL_TESTS.md · a software GPU draws on the CPU, so fps in CI measures SwiftShader, not the engine.
- 2026-10-29 · test models · generated by `packages/three/scripts/generate-models.mjs` (three's GLTFExporter + glTF-Transform + draco3d 1.5.7 + ktx2-encoder, dev dependencies of the package only), CC0 · no third-party model, reproducible; draco3d 1.5.7 because 1.5.8+ were less than two weeks old.
- 2026-10-29 · @types/three · a dependency (not dev) of `@blacklight/three` · its public types (`object3d: Group`, `rotation3d: Euler`) need them in games.
- 2026-10-29 · core change (3e) · `packages/core/src/modules/` (defineModule, ModuleHost, schemas `t`, Network/OfflineQueue, nativeModule) exported from `@blacklight/core`; `@blacklight/core/schema` entry (no renderer, for Node/Electron main); `GameConfig.modules`; `CreateGameOptions.modules`; `game.modules` getter; modules set up after `plugins`, before the first scene; new `game.destroy()` disposes modules then the renderer · MOD-01/02 need one host in core; platform plugins (desktop, mobile) must stay in `plugins` so `context.platform` is theirs when modules start.
- 2026-10-29 · module discovery · `modules: { <name>: {options} }` in game.config.ts; the CLI resolves each name to `modules/<name>/<name>.module.ts`, then `@blacklight/module-<name>`, `@blacklight/<name>`, `blacklight-module-<name>`, `@scope/blacklight-module-<name>` from the game's dependencies, and serves `virtual:blacklight/modules` (definitions found among each file's exports by a brand) · game.config.ts stays plain data the CLI can load in Node without bundling module code.
- 2026-10-29 · module types · `.blacklight/types.d.ts` gets `Register.modules` (API via `ModuleApiOf<typeof import(pkg), name>`) and `Register.moduleConfigs` (option input types) appended by `generateTypes` · `game.modules.sqlite` and the `modules` entries of game.config.ts are typed without code generation in the packages.
- 2026-10-29 · shared CLI edits (3e) · `packages/cli/src/vite.ts`: generated main.ts imports `virtual:blacklight/modules` and passes `modules` to createGame; `blacklightModules()` plugin (packages/cli/src/modules.ts, `enforce: 'pre'`) added to createViteConfig; generateTypes appends the module types; `cli.ts`: `registerRegistryCommands(cli)` · keeps the 3e logic in its own files.
- 2026-10-29 · platform-limited modules · a module whose `platforms` excludes the current platform (or whose dependency was skipped) is not set up and `game.modules.<name>` is `undefined`, typed `Api | undefined` · a desktop-only module must not stop a web build.
- 2026-10-29 · module events · `context.events` is one bus shared by the game's modules (`ModuleEvents`, extended by declaration merging); each official module also exposes `on()` on its API · games listen on the module they use; modules can talk without importing each other.
- 2026-10-29 · ModuleSaves hook · `context.saves` is `game.save` when it implements `ModuleSaves` (`slots()`, `exportSlot(slot)`, `importSlot(slot, bytes)`, `onSaved(listener)`), else `undefined` · the save system (3c, `packages/core/src/save/`) only has to implement these four members for cloud-save to work; exported bytes are the portable (still encrypted) slot.
- 2026-10-29 · offline queues · `context.network.queue(name, handler)` persists items as JSON in `modules/<module>/queue-<name>.json`, delivers in order, exponential backoff 1 s → 5 min, `DropItem` discards; online state = `navigator.onLine` and failed/succeeded requests; `resume` platform events and `online` flush · MOD-02 "offline queue with retry"; browsers never announce a server coming back, so backoff keeps probing.
- 2026-10-29 · module shutdown · modules are disposed on `game.destroy()` and on `pagehide` without `persisted` (tab or window closed) · there was no shutdown hook; Electron and Capacitor close the page too.
- 2026-10-29 · define-native contract · `packages/native/src/define-native.ts` (no imports) exports `defineNative({ name, functions, setup?, dispose? })` and `fn(schemas, run)`; the result is a `NativeModule` with `name`, `methods`, `call(method, args, context)` (refuses unknown names, own properties only, checks argument count and schemas), `setup(context)`, `dispose(context)`, brand `blacklightNative`; `context = { gameId, dataDir, dev }`. The desktop main process must: register each native part of the configured modules (official module packages export it as `./native`, local modules as `modules/<name>/native.ts`), call `setup` once, answer `invoke(name, method, ...args)` from the renderer with `call(method, args, context)`, call `dispose` on quit, and re-export `defineNative`/`fn` from `@blacklight/native` plus a `./define-native` export · the merge only connects the registry; `@blacklight/module-sqlite/native` imports `@blacklight/native/define-native` (tsconfig path + vitest alias to the source until the package exists; add `@blacklight/native` as an optional peer dependency of module-sqlite at merge).
